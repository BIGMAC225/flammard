## 0. Decisions (answered 2026-09-26)

- **Logins:** individual accounts for everyone. There is no Azure or Entra ID, so each person has an email and password inside Flammard, stored as a scrypt hash. Setup and reset links are generated by an admin, so no email service is needed. The shared password stays as a fallback during rollout.
- **Teams:** keep Leadership and Management as they are for now.
- **Email:** only meeting recaps, sent through Zapier. Flammard posts a signed webhook when a meeting concludes or is approved, and a Zap emails attendees.
- **Kept from the skip list:**
  - Facilitator/implementer tools, so Russell can run everyone's meetings. That means health across teams, meeting prep, toolkit tracking and custom tips.
  - An importer from Ninety (ninety.io) for current issues and to-dos, plus rocks, headlines and the scorecard when present.

### Original questions

1. **Individual logins or keep the shared password?** About a third of the list depends on knowing *who* is using the app. That includes owners you can pick from a list, "my" to-dos and rocks, per-person meeting ratings, @mentions, notifications, read receipts on processes and the People Analyzer. The options are below; B is recommended.
   - **A. Keep one shared password** and add a "Who's here?" picker that remembers a person per browser. This is cheap, but it gives no real permissions.
   - **B. Individual accounts with a magic link by email or Microsoft sign-in.** Keep the shared password as a fallback during rollout. This makes roles possible: Owner/Admin, Manager, Member, Observer.
2. **Teams:** keep only Leadership and Management, or allow any number of teams (departments, 1:1 pairs)? Recommendation: any number.
3. **Quarters:** keep the custom named periods, or add company quarter dates (success.co lets admins set quarter start dates)? Recommendation: keep periods and add a "quarter" flag and dates so the EOS quarterly tools line up.
4. **Email:** is it OK to send email (meeting recaps, reminders, invites)? This needs an email provider such as Postmark or Resend, or Microsoft 365 SMTP.
5. **Anything in the ⏭ rows you *do* want?**

### How the Opus agents would build it
- **Planner (1 Opus):** turns the phase into a technical spec: schema migration, API routes, components, and a test checklist. It also splits the work into independent tasks. Nothing is built until you approve the spec.
- **Builders (2–4 Opus, parallel, each in its own git worktree):** each takes one task, writes the code and the migration SQL, and runs `astro build`.
- **Reviewer (1 Opus):** reviews each builder's diff for bugs and consistency before it's merged into the phase branch.
- **Integration:** one PR per phase, a Netlify deploy preview to click through, then the upgrade SQL is run in Neon, then the merge.
- Every schema change stays additive and re-runnable (like `db/schema.sql` today), so the live site keeps working between steps.
